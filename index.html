Case study

Ghaya Go

Software Engineer · Feb–Aug 2026 · Pre-launch · Modular monolith

System context

One NestJS API serves two clients. The CMS never writes curriculum tables directly—it calls signed /cms/v1/* endpoints. Mobile consumes Clerk-authenticated /users/me/* routes. Business rules live in the API; clients share Zod schemas and types. The surface is 54+ HTTP routes across six controllers: 22 learner, 28 CMS write, plus public catalog, webhooks, and health.

Engineering decisions

Modular monolith
I kept one deployable because cross-module transactions matter more than service boundaries at this team size. The module split is real — I'd extract later, not now.
Aggregated REST endpoint
GraphQL would have been prettier on paper. Two clients, one backend engineer, known mobile shape — I shipped /users/me/learn and cached it instead.
Explicit cache-aside
I write invalidation beside the write path on purpose. Hidden framework caching is how you get stale learn tabs and no idea why.

Private pre-launch team product. Primary scope: backend and API integration. Stripe validated in test mode; no live production traffic claimed.

What broke

Real bugs from Ghaya — not hypothetical war stories.

  1. 01

    Stripe renewals updated nothing

    Symptom
    Checkout worked; subscription renewals silently failed to update period end.
    Cause
    The handler cast event.data.object once as a Checkout Session and reused that variable for invoice.payment_succeeded.
    Fix
    Branched per event type, mapped fields from Stripe.Invoice, recorded the event id before processing so retries are no-ops.
  2. 02

    Learn tab over-fetching

    Symptom
    Mobile cold load fired four or five parallel API calls before the trail UI could render.
    Cause
    No aggregated endpoint — progress, modules, course progress, and lesson percentage each had their own route.
    Fix
    Built GET /users/me/learn, added read indexes in migration 009, cached the snapshot for 30s. Down to about two calls.
  3. 03

    Points farming via scope bypass

    Symptom
    Any authenticated learner could post progress for any published task, not just their active course.
    Cause
    Lesson, quiz, and task IDs were not verified against the user's active course before awarding points.
    Fix
    Added active-course assertions on curriculum-read and gamification paths.
