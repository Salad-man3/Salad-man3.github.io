Ribat, under the hood رباط

Many mosques share one database, so the hard part is making sure one mosque can never see another's people, and that a phone that was offline for a whole class can never count anything twice.

github.com/Salad-man3/ribat

The shape

React PWA and teacher phones call one NestJS API. Every request passes rate limit, session, CSRF, organization, and permission checks before a Prisma tenant extension scopes queries to PostgreSQL; workers drain the outbox on Redis.

Screens

Decisions I'd defend
Security
Tenant scoping in one place

A Prisma extension adds the mosque ID to every tenant query and throws if it is missing.

Why
A forgotten where fails a test instead of leaking data.
Proof
E2E runs two mosques; the other's records return 404.
Sync
Offline writes carry no authority

Each tap gets an idempotency key; replay checks permissions as they are now.

Why
Resent batches come back as duplicates, not double rows.
Cost
Replay must refuse a teacher removed mid-class.
Data
Memorization as a ledger

Recitation logs are append-only; mistakes are voided with a reason, never edited.

Why
Summaries rebuild from the ledger in the same transaction.
Cost
More rows than updating a single progress field.
Auth
Cookie sessions instead of JWTs

Sessions live in the database so sign-out and password change end access immediately.

Why
No long-lived token to revoke across devices.
Cost
CSRF token on every write.
Auth
No self-signup

Staff hand out a one-time setup code; passwords hashed with Argon2id.

Why
No email or phone OTP at signup — mosques avoid paid SMS/email verification services. Users still get in without an inbox. Ribat is open source (AGPL); anyone who wants self-signup can add OTP on top.
Cost
Staff must create every account.
Events
Outbox once a second consumer existed

Events write with the change, idempotent per handler, dead-lettered after five failures.

Why
Notifications and nightly jobs must not fire if the row rollbacks.
Cost
Dispatcher and worker to operate.
